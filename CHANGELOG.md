## v3.4.4 — Real automatic updates via electron-updater (2026-09-18)

Playnest now checks GitHub Releases for new versions and updates itself —
no more manually re-downloading the installer for routine updates:

- **electron-updater wired in.** `electron/main.cjs` calls
  `autoUpdater.checkForUpdatesAndNotify()` a few seconds after the window
  opens (non-blocking, background). The `build.publish` config in
  `package.json` points at the public
  `ofirshudari1-ship-it/playnest` GitHub repo, which is where
  electron-builder now also uploads `latest.yml` alongside each release
  build — that file is what electron-updater reads to know a newer
  version exists.
- **Download happens automatically**, and when it finishes a native
  "Restart now / Later" dialog offers to install immediately; if the user
  picks Later, the update installs automatically on the next normal quit
  (`autoInstallOnAppQuit`).
- **Fails quietly.** No internet connection, GitHub unreachable, or any
  other update error is logged to the existing crash log and otherwise
  ignored — it never blocks startup or crashes the app.
- Dev builds (`NODE_ENV=development`) skip the update check entirely,
  since there's no packaged app / update feed to hit.
- No other app behavior touched — the running-instance check and
  installer install-path handling from v3.4.2/v3.4.3 are untouched.

## v3.4.3 — Real welcome/finish page copy + brand-colored primary button (2026-09-17)

Installer-only pass, no app code touched. Follow-up to v3.4.2's branded-
bitmap pass — this closes the remaining gap between "the installer looks
branded" and "the installer wizard actually behaves like a branded product":

- **Welcome page added.** Before this release the assisted (non-oneClick)
  NSIS installer had *no welcome page at all* — Modern UI 2 only shows one
  if a `customWelcomePage` macro explicitly calls `!insertmacro
  MUI_PAGE_WELCOME`, and `build/installer.nsh` never defined that macro.
  It now does, with real product copy (auto library scan, no-cloud/local
  data, auto-rescan, quick-launch hotkey) via `MUI_WELCOMEPAGE_TEXT`, in
  English and Hebrew (`LangString`, following the installer's existing
  bilingual language-selector setup).
- **Finish page copy added** the same way, via `MUI_FINISHPAGE_TEXT`.
- **Primary button brand color.** NSIS/Modern UI 2 has no supported way to
  reshape or recolor a standard Next/Back/Cancel button — those are
  theme-drawn by Windows. The real, working technique used here: disable
  uxtheme visual-style theming on the Next/Install/Finish button handle
  specifically (`uxtheme::SetWindowTheme` via NSIS's bundled `System`
  plugin), which makes the native `SetCtlColors` instruction actually take
  effect. Net result: the primary button loses the native rounded Windows
  11 chrome and renders flat/classic in the brand violet — a real, visible
  change, not a shaped custom bitmap button. Back/Cancel are left native
  on purpose. Color used is `#7053e5` (not the raw `--accent` `#7c5cff`) —
  audited against WCAG AA: the raw accent vs. white button text is only
  4.35:1, under the 4.5:1 AA threshold for normal-size text; darkened
  ~10% to `#7053e5` clears it at 5.18:1 while staying recognizably the
  same violet.
- `build/installer.nsh`'s existing running-instance check (customInit/
  customUnInit/customCheckAppRunning) is untouched.

Version bumped to 3.4.3 (PATCH) to document and rebuild.

## v3.4.1 — Fixed a real display bug + dead-CSS cascade cleanup (2026-09-17)

Reported by the user with a screenshot: the Analytics page's genre bars all
rendered at the same width regardless of actual playtime, and stat numbers
looked off. Root-caused to two separate, real bugs — not just one:

**Bug 1 — divide-by-zero in the genre bar width calculation.**
`AnalyticsView.tsx` computed each bar's width as
`g.minutes / Math.max(...allGenres.map(x => x.minutes))`. For a freshly-
scanned library with no recorded playtime yet (every `minutes` is `0`),
`Math.max(...)` is `0`, so the division is `0/0 = NaN`, and `width: NaN%` is
invalid CSS — every bar silently renders identically instead of reflecting
real proportions. Fixed with a guard: when there's no playtime data yet,
bars fall back to being proportional by game count instead of collapsing to
a meaningless flat line.

**Bug 2 — dead CSS from long-deleted components cascading into live pages.**
Several "gaming tool" components deleted in earlier passes (v3.1.1's mock-UI
purge, and others before that: `GamingStatsShowcase`, `GamingPerformanceBooster`,
`GameOptimizer`, `NetworkOptimizer`, `GamingSessionTracker`, `MoodGamePicker`,
`OnboardingWelcome`) had their component files removed, but their CSS rules
were never cleaned out of `global.css`. Because several of them reused
generic classnames also used by real, live components — `.stat-tile`,
`.stat-value`, `.stat-label`, `.stats-grid`, `.game-card`,
`.game-card.selected` — their leftover rules partially cascaded into pages
that are very much still in use:
- Every stat number app-wide (Analytics, Insights, Settings) silently picked
  up a `-webkit-text-fill-color: transparent` gradient-text-clip effect and
  an unintended `:hover` lift from the deleted "Gaming Stats Showcase".
- **Selecting a game card in multi-select mode** applied *both* the real
  selection outline *and* an unwanted gradient background + glow left over
  from the deleted "Game Optimizer" — two conflicting selected-states
  stacked on the same element.

Removed ~400 lines of dead CSS (`GamingStatsShowcase`, `GamingPerformanceBooster`,
`GameOptimizer`, `NetworkOptimizer`, `GamingSessionTracker`, `MoodGamePicker`,
`OnboardingWelcome`, and stray `.badge-icon`/`.badge-text`/`.rec-title`/
`.rec-game` remnants), keeping only the classnames genuinely still in use
found within those blocks (`.setting-toggle`/`.setting-info`/`.setting-title`/
`.setting-desc`/`.toggle-btn`, used by PerformanceMode and SettingsPanel).
Compiled CSS bundle shrank from ~47 kB to 32.7 kB as a direct result —
concrete evidence this was real dead weight, not just a style nit.

Verified: full test suite still green (19/19), and a live launch against the
real 149-item user profile completed with no errors.

## v3.4.0 — Automatic rescan, grid density, quick-launch hotkey (2026-09-15)

A product-improvement pass grounded in a look at how Playnite/GOG Galaxy
handle a live library (WebSearch, 2026-09) plus a read-through of the actual
scan/sort code, rather than a redesign — this app was already close to
`_AUDIT/STANDARDS.md` compliant going in.

**Added**
- Automatic background rescan (`electron/main.cjs` `runAutoRescanIfDue`,
  `electron/store.cjs` `autoRescanHours`/`lastScanOptions`): an opt-in
  "Never / Every day / Every week" setting (`src/components/Settings/
  SettingsPanel.tsx`) that quietly repeats the user's last manual scan on a
  schedule, so newly installed games/apps show up without reopening the setup
  wizard by hand. Entirely local — reuses the existing filesystem/registry
  scan and the existing `library:updated` push, no new network calls, no
  cloud AI. Off by default; never runs before the user has completed setup
  at least once. Checked once at launch (catches up if the app was closed
  past the due date) and then on a 30-minute poll for the life of the process.
- "NEW" badge on library cards (`src/components/Library/GameCard.tsx`,
  `src/helpers.ts` `isRecentlyAdded`) for anything added to the library in
  the last 7 days — mirrors the "recently added" cue GOG Galaxy/Playnite
  both surface. Suppressed on favorited items so it never collides with the
  star badge, which already owns that corner.
- "Most played" and "Last played" sort options in the library's sort-by menu
  (`src/components/FilterMenu.tsx`).
- Grid density control — Compact / Comfortable / Large card sizes for the
  library grid (`src/components/FilterMenu.tsx`, `src/components/Library/
  CategoryRow.tsx`, `src/styles/global.css`), inspired by the density option
  Steam's own library view offers. Stored per-user in `settings.gridDensity`
  (`electron/store.cjs`, `src/types.ts`), applied via a `--card-w`/`--card-gap`
  CSS custom property pair so both the grouped (row) and ungrouped (grid)
  layouts stay in sync from one setting.
- Global quick-launch hotkey (`Ctrl+Shift+L`, `electron/main.cjs`
  `applyQuickLaunchHotkey`/`bringMainWindowToFront`): brings Playnest to the
  front and focuses search even when it isn't the focused app, in the spirit
  of Playnite's and GOG Galaxy's overlay/quick-launch shortcuts. On by
  default, toggleable in Settings (`settings.quickLaunchHotkeyEnabled`).
  Registration is best-effort — `globalShortcut.register()` returns `false`
  rather than throwing when another running app already owns the
  combination, so it silently no-ops instead of crashing; unregistered
  cleanly on `will-quit`. Ships as a fixed combination behind an on/off
  toggle rather than full remapping (`STANDARDS.md` §12.4 asks for the
  latter) — a documented, scoped gap, see `SPEC.md` §9.
- Proactive "needs attention" check (`src/App.tsx`, reusing the existing
  `library:verify` IPC and a new `computeNeedsAttention` helper in
  `src/helpers.ts`): once per fresh library load, silently re-runs the same
  local `fs.existsSync` check the "Verify Library" button in Settings already
  offered manually, plus flags favorited items added 2+ weeks ago that still
  show zero playtime. Surfaces as a single info toast ("Needs attention: N
  broken shortcuts, M unplayed favorites...") pointing at Settings → Library
  Health, instead of a broken shortcut sitting unnoticed until the user
  happens to open Settings. No network call, no cloud AI — same rule-based
  local heuristic the rest of the app's "Smart Features" already use.

**Fixed**
- `sortBy: 'playtime'` and `'lastPlayed'` existed in the `Settings` type and
  were selectable in principle, but `sortItems` (`src/helpers.ts`) had no
  `case` for either, so picking them silently fell through to name sort —
  the sort-by dropdown didn't even expose them as a symptom of the same gap.
  Both are now implemented (unplayed/never-played items sort to the bottom,
  not the top) and exposed in the dropdown.
- **Performance:** `library:get` (`electron/main.cjs`) synchronously
  re-read and re-base64-encoded every cover-art JPEG from disk on *every*
  call — and favoriting, hiding, or tagging a single item each trigger a
  full library reload from the renderer, so clicking one star could mean
  re-reading and re-encoding a few hundred cover images on the main process
  before the favorite even seemed to register. Cover art is
  content-addressed by item id and never rewritten once fetched, so it's
  now cached in memory for the life of the process (`coverDataUrlCache`),
  invalidated only on an actual new-cover fetch. Startup and post-scan
  behavior is unchanged; every toggle after that no longer touches disk.
- **Performance:** `getInstalledPrograms` (`electron/registry.cjs`) queried
  the three uninstall registry roots (`HKLM`, `HKLM\WOW6432Node`, `HKCU`)
  one after another with `reg query /s`, each walking potentially hundreds
  of subkeys — now run concurrently with `Promise.all`, so this part of
  every scan takes roughly as long as the single slowest root instead of
  the sum of all three.
- **Performance/responsiveness:** a deep scan's folder walk
  (`electron/scanner.cjs` `scanDriveFolders`/`scanRegistryPrograms`) ran as
  one unbroken synchronous block — `fs.readdirSync`/`fs.statSync` and
  fast-glob's `.sync()` never yield to Node's event loop, and Electron's
  async IPC (including the `scan:progress` messages meant to show live
  "Checking &lt;path&gt;" status) only actually gets delivered once control
  returns to that loop. Progress text appeared to batch up and jump at the
  very end of a deep scan instead of updating live, and the app was
  unresponsive to any other IPC for the scan's full duration — the "no UI
  freeze" failure `STANDARDS.md` §2 calls out. Added a `yieldToEventLoop()`
  (`setImmediate`-based) checkpoint once per folder in `scanDriveFolders` and
  every 20 items in `scanRegistryPrograms`, so queued progress/IPC actually
  flushes during a long scan instead of only after it finishes. Scan
  wall-clock time is unchanged; only responsiveness during the scan improves.

**Changed**
- `src/components/FilterMenu.tsx` had no `t()` calls at all — "Group by" /
  "Sort by" / category checkbox labels were hardcoded English even after
  Hebrew translation was otherwise completed in v3.3.1. Converted to `t()`
  using the new `filterMenu.*` locale keys (reusing the existing
  `sidebar.games`/`applications`/`system` keys for the category checkboxes),
  so it now switches with the rest of the app instead of staying
  English-only in Hebrew mode.
- `.empty-state` gets a brief fade/slide-in on mount and a subtle icon lift
  on hover (`src/styles/global.css`) instead of appearing instantly static.
- Added `.new-badge` styling reusing the existing accent gradient
  (`--accent`/`--accent-2`, violet/teal, defined in `src/styles/global.css`)
  rather than introducing a new color. Note: the generic task brief for this
  pass named a `#22b8a0`/`#0c4d43` teal palette, which doesn't match this
  project's actual established palette (no `assets/BRAND.md` exists yet to
  document one formally) — not applied, to avoid an inconsistent rebrand.

Full reasoning in [SPEC.md §9](SPEC.md#9-standardsmd-compliance-pass-v321).

## v3.3.0 — STANDARDS.md compliance pass (2026-09-14)

A structural and UX pass bringing Playnest in line with the cross-project
standard defined in `_AUDIT/STANDARDS.md`. Full reasoning in
[SPEC.md §9](SPEC.md#9-standardsmd-compliance-pass-v321).

**Folder structure**
- Installer now lands in the project root (`Playnest-Setup-<version>.exe`),
  not buried in a `release/` subfolder.
- `docs/PRODUCT_SPEC.md` → `SPEC.md` (project root).
- Marketing pages (`landing-page.html`, `business-presentation.html`) moved
  into `site/`.
- Brand assets (icon, logo, installer graphics) split out of `build/` into a
  dedicated `assets/` folder; `build/` now holds only generator scripts and
  build-time config.
- Vite's compiled web output moved from a root-level `dist/` to
  `build/dist/`; electron-builder's own working output moved from a
  root-level `release/` to `build/release/` — both are build intermediates,
  not deliverables, and don't belong in the root.
- Removed a fully orphaned, hand-written NSIS script from a
  pre-electron-builder era that had been sitting unused in `build/`.

**New: `version.json`, `tests/`, `locales/`**
- `version.json` is now the single source of truth for the app version,
  synced into `package.json` on every build and shown (with build date) in
  the About screen.
- `tests/` added: 15 smoke tests (`node --test`) covering the scanner's
  installer-exe filtering, deduplication, and final usability gate; locale
  file completeness (en/he key parity, no empty strings); and version sync.
- `locales/en.json` + `locales/he.json`: full bilingual UI infrastructure
  (`src/i18n.ts`) with live RTL switching. Translated: sidebar, topbar,
  empty states, splash screen, error screen, setup wizard, and the full
  Settings panel. A language toggle is always visible in the topbar.
  Secondary detail pages (Performance Mode, Streak Tracker, System Monitor,
  Analytics/Recommendations/Insights prose) remain English-only for now —
  a scoped, honest follow-up rather than a claimed 100%.

**Onboarding fixed**
- The setup wizard used to force itself open *every time* the library was
  empty — including right after a user deliberately backed out, since there
  was no skip button at all. Now gated by a persisted first-run flag, with a
  visible Skip button and Esc-to-skip on every step (with a confirmation,
  not a silent exit), reachable again anytime via Settings → "Run Setup
  Wizard Again."
- The welcome screen now also carries the installer's own English/Hebrew
  language toggle, so language and setup are chosen together.

**Splash, theme, updates**
- Splash screen now holds for a minimum of 900ms so a fast startup never
  flickers by unshown.
- Theme gained a `system` option that follows the OS light/dark setting live
  (`matchMedia`), alongside the existing manual Dark/Light override —
  `system` is now the default.
- The `app:checkForUpdates` IPC method existed but nothing ever called it —
  wired to a dismissible banner. Fixed a real bug found in the process: the
  version comparison used plain string comparison (`"3.9.0" > "3.10.0"` is
  `true`, which is wrong), replaced with a proper numeric comparison. Still
  points at a placeholder repo — needs the project's real GitHub repo (or a
  hosted `latest.json`) wired in before it does anything in practice.

**Installer**
- English/Hebrew language selection was already present (v3.2.0) — verified
  still correct against the new `assets/` paths.
- Installer already had per-user/per-machine choice, custom install
  directory, desktop/Start Menu shortcuts, EULA, and single-instance
  detection at the app level — all confirmed still working after the
  restructure.

**Real bug caught by testing against an actual existing profile**: after
wiring the first-run flag, ran the built app against a real 149-item library
from an earlier session — a returning user with existing games would have
hit the "first run" wizard anyway, since their profile predates the
`setupWizardSeen` field entirely. Fixed the migration: a profile with no
setup flag *and* an existing library is treated as already-onboarded, not
first-run. Verified against the same real profile after the fix
(`setupWizardSeen` correctly backfilled to `true`).

**Follow-up (same day): installer-level "already running" check added**
`_AUDIT/STANDARDS.md` flags this as missing from every tool in the project
except SnapAI — Playnest was no exception. `app.requestSingleInstanceLock()`
already stopped a second *app* instance from opening, but did nothing to
stop the *installer* from overwriting files while Playnest was still open
and holding them locked (the exact scenario the standard calls out: file-
lock corruption mid-update). Added `build/installer.nsh`, a custom NSIS
hook (`customInit` / `customUnInit`) that checks via `tasklist` before both
install and uninstall, blocking with a Retry/Cancel prompt until the app is
actually closed. Verified the custom script compiles cleanly as part of a
full `npm run dist` run (NSIS fails the build hard on a macro syntax error,
so a clean build is a real compile-check, not just "no errors printed").

## v3.2.1 — Security fix: removed shared API key (2026-09-14)

An audit found that `electron/config.cjs` shipped a hardcoded, shared
SteamGridDB API key as a "works out of the box" fallback. That key was
compiled into every installer and effectively public. Fixed:

- Removed the hardcoded key from `electron/config.cjs` — the fallback is now
  empty, so cover art requires each user's own free SteamGridDB key.
- Updated the Settings hint to point users to get their own key instead of
  implying a built-in one exists.
- **The leaked key should be treated as compromised** — revoke/rotate it from
  the SteamGridDB account it belongs to.
- No other secrets were found in the project (frontend bundle was checked —
  the key never leaked into `dist/assets`, only into the packaged installer's
  Electron main-process code).

## v3.1.3 — Library-leak fix (2026-09-14)

**Real bug:** every Tools page (Performance Mode, Streak Tracker, System
Monitor) rendered the full game/app library grid underneath its own content.
Cause: the flag that decides whether to show the library grid
(`isLibraryView`) was a hand-maintained blacklist of "pages that aren't the
library" — it listed 6 pages, but 3 new Tools pages were added after that
list was written and nobody came back to add them to it. Same root cause
also left the sort/filter dropdown showing on every Tools page despite
having nothing to sort or filter there.

**Fix:** replaced the blacklist with a whitelist — `isLibraryView` now checks
*for* the actual library views (`all`, `games`, `applications`, `favorites`,
`system`, `hidden`, collections) instead of checking *against* everything
else. A future tool page is excluded by default instead of needing to be
remembered.

## v3.1.2 — Simplification Pass (2026-09-13)

A UX audit of the tools added in v3.1.1, prompted by feedback that the sidebar
had become cluttered and confusing even after removing the fake tools.

### Real bug fixed: two different features both called "Game Mode"
"Auto Game Mode" (the Windows Game Mode registry toggle) and "Work/Game Mode"
(the power-plan switcher) each shipped as separate pages, and the power-plan
switcher's third option was *also* labeled "Game Mode" — so the sidebar showed
two unrelated features under names a user couldn't tell apart. Merged both
into a single **Performance Mode** page with two clearly-separated controls

## v3.1.1 — Reality Pass (2026-09-13)

A full audit of every "gaming tool" shipped in v3.1.0, prompted by user feedback
that several tools were pure mock UI with no real functionality, the scanner
showed duplicate games and installer files instead of real shortcuts, and cover
art fetching blocked the library from appearing.

**Follow-up correctness pass (same day):** a post-ship review caught two real
bugs in this release's own new code before they'd have surfaced for users:
- The Streak Tracker computed "today" from `Date.toISOString()`, which is a
  UTC date — for anyone east of UTC (including Israel) that flips over hours
  before local midnight, so a streak could silently break at 2–3am local time
  instead of at midnight. Fixed to use the local calendar date everywhere the
  daily activity log is read or written.
- The installer-exe filter used a regex ending in `\b`, which can't match
  between two word characters — so it missed the single most common real
  installer naming pattern (`Setup64.exe`, `vcredist_x64.exe`, keyword
  immediately followed by digits/underscore). Replaced with a
  not-followed-by-a-letter check, verified against 20 real exe names
  (installers correctly excluded, games like `Undertale.exe`/`Settlers.exe`
  correctly left alone).
- The background art-fetch loop could throw if the app window closed mid-fetch
  (sending to a destroyed webContents) and left a stuck "fetch in progress"
  flag on any unexpected error; both are now guarded.
- Removed a misleading "try running as administrator" hint on the Game Mode
  toggle — it writes to `HKCU`, which never needs elevation; a real failure
  there is something else.

**Live-tested against this machine's actual Windows install**, not just
code review: verified the exact `powercfg /list` / `/getactivescheme` output
this app parses, and round-tripped a real `reg add` / `reg query` /
`reg delete` cycle against the Game Mode key (state restored afterward) to
confirm the registry read/write logic behaves exactly as coded.

### Scanner fixes
- **No more installer files masquerading as games.** Executables named like
  `setup.exe`, `unins000.exe`, `vc_redist*.exe`, etc. are now excluded when
  picking a folder's "main" executable, and registry entries whose
  `DisplayIcon` points at an uninstaller are repaired by searching the real
  install folder for the actual program.
- **Nothing unreachable gets shown.** After scanning, any entry that has
  neither a working executable path nor a real install folder on disk is
  dropped entirely — no more dead tiles that fail to launch or open.
- **Better deduplication.** Games are now deduped both by normalized name and
  by install path, so two registry/folder entries pointing at the same folder
  collapse into one.

### Faster startup, background artwork
- Scanning now saves and returns your library **immediately** after the
  filesystem/registry scan finishes. Cover art fetching (the slow part) now
  happens in the background afterward, with the UI refreshing quietly as
  covers arrive instead of blocking the whole library behind it.

### Gaming tools — audited, fixed, or removed
Every tool was checked for whether it does something real. Nine tools were
pure mock UI (hardcoded numbers, `Math.random()`, fake "connected" states)
with zero backend integration and were **removed**:

| Removed tool | Why |
|---|---|
| Discord Rich Presence | No real Discord RPC connection — just a static "Connected" badge |
| Streaming Optimizer | No real network/encoder changes |
| VPN Checker | No real VPN detection |
| RGB Controller | No RGB hardware SDK integration possible without vendor drivers |
| AI Gaming Coach | Fabricated tips with no access to real game telemetry |
| Friend Activity Tracker | Hardcoded fake friends list, no social API |
| Game Comparison | Hardcoded prices for 3 games, no real store API |
| Advanced Statistics | Duplicate of the real Analytics/Insights views, but with fake numbers |
| Game Recorder | No real screen-capture pipeline wired up |

Four tools were **rebuilt to be genuinely functional**:

| Tool | What's real now |
|---|---|
| **Auto Game Mode** | Reads/writes the actual Windows `AutoGameModeEnabled` registry key |
| **Work/Game Mode** | Switches your real Windows power plan via `powercfg` |
| **Streak Tracker** | Computed from an actual daily activity log recorded every time you launch something |
| **System Monitor** (was "PC Benchmark") | Live CPU/RAM/temperature from real hardware sensors — no fake FPS number |

A new **Tools** page (sidebar → Insights → Tools) lists every remaining tool
and states plainly what it does and why it's marked "working."
